# 2026-10-02 창고 Box 요청 경로 및 0x14 연결 재분석_GPT자문

## 핵심 결론

WareHousePanelMono.OnClickOpenBox @ 0104cd6c를 다시 확인한 결과, 함수 자체에는 직접적인 KCPTube.Send / NetworkCenter.Send 호출이 확인되지 않는다.

따라서 운영 PCAP에서 확정된 OpCode 0x14를 OnClickOpenBox와 직접 동일시하지 않는다.

현재 구조는 다음처럼 분리한다.

창고 진입:
Bootstrap OpCode=2 → OpInfo.Items → DataCenter.MergeItem → DataCenter +0x78 cache → WareHousePanelMono.InitData → Warehouse UI

Box 선택:
currentClickItem → OnClickOpenBox → GetChooseItem → isBoxItem → Box 관련 화면

실제 요청:
Box 관련 화면/controller → request object → KCPTube.Send → 실제 OpCode → Server response

## OnClickOpenBox 확인

OnClickOpenBox의 주요 호출은 GetChooseItem, Ali.GetExcelData<object>, AliothExtensions.isBoxItem, GUIScreenManager.ShowScreen 등이다.

즉 현재 정적 증거상 역할은 선택 Item을 확인하고 Box 관련 화면으로 넘기는 단계다. 서버 request 생성 함수로 확정할 근거는 없다.

GetChooseItem @ 0104ccac은 m_currentClickItem을 반환한다.

## RegisterCallBack 추가 확인

WareHousePanelMono.RegisterCallBack @ 0104b528에는 btn_openBox, Ali.OnProccessRequestFinish, BaseMono.RegisterDataProccessCallBack가 확인된다.

callback 등록값으로 0x2A와 0x6E가 사용된다. 이 값들은 현재 STRONG 수준의 Warehouse data-process callback 값으로 본다.

중요하게도 0x2A/0x6E를 wire OpCode로 확정하지 않는다.

## 운영 PCAP 0x14

다음은 계속 CONFIRMED로 유지한다.

frame 428: Client → Server, OpCode=0x14, chapterId=20000100, boxIndex=5

frame 430: Server → Client, OpCode=0x14, Chapter snapshot 포함

따라서 Local Server의 0x14 계약 자체는 유지한다. 다만 실제 Client 생성 함수는 아직 확정하지 않는다.

## BoxStatus

ProtoChapter 구조는 +0x10 Id, +0x14 Status, +0x18 Progress, +0x1C BoxStatus로 유지한다.

IsBoxReceived(mask) = (BoxStatus & mask) != 0이며 mask = 1 << boxIndex이다.

boxIndex=5이면 UI 검사 mask는 0x20이다.

BoxStatus 구조 자체는 CONFIRMED다. frame 430의 특정 protobuf field가 BoxStatus의 어느 field number인지의 1:1 매핑은 별도 검증 대상으로 둔다.

## 다음 실기기 검증

로그인 → 메인 → 창고 → Box 선택 → Box 오픈 순서로 실행한다.

Box 오픈 직전/직후 KCPTube.Send의 request class, OpCode, SerialNumber와 KCPTube.TryRead/DataCenter.ProccessRequestRes의 response class, OpCode, SerialNumber를 비교한다.

판정:

A. Box 오픈 직후 OpCode=0x14이면 운영 PCAP frame 428과 runtime을 직접 연결한다.

B. 다른 OpCode이면 해당 opcode를 별도 계약으로 추적하고 0x14와 분리한다.

C. Send가 없으면 OnClickOpenBox 이후 ShowScreen 대상의 Box controller/Lua 경로를 추적한다.

## Local Server 기준

Bootstrap OpCode=2와 운영 PCAP의 OpCode=0x14는 별도 확정 계약으로 유지한다.

Box UI → 실제 request object → 0x14 연결은 runtime Send 확인 전까지 확정하지 않는다.

다음 목표는 OnClickOpenBox → ShowScreen → Box 관련 controller → KCPTube.Send → 실제 OpCode를 연결하는 것이다.
