# 2026-10-02 로컬 서버 구축 중심 분석 범위 및 작업 원칙

## 1. 목적

이 프로젝트의 최종 목표는 게임 내부 전체를 역공학하는 것이 아니라, **원본 클라이언트가 로컬 서버와 정상적으로 통신하고 필요한 화면과 기능을 사용할 수 있도록 Local Private Server를 구축하는 것**이다.

게임 내부 구조를 모두 알아내는 것보다 클라이언트와 서버 사이의 통신 계약을 확인하고 재현하는 데 분석 자원을 집중한다.

## 2. 분석의 중심

기본 추적 경로:

```text
Client Action
  ↓
Request Creator
  ↓
Serialize / Encrypt
  ↓
Network Send
  ↓
Server Command Handler
  ↓
필요한 Player State 처리
  ↓
Response 생성
  ↓
Serialize / Encrypt
  ↓
Network Receive
  ↓
Decrypt / Decompress / Deserialize
  ↓
Client Handler
  ↓
화면 및 State 반영
```

기능별로 아래 항목을 확인한다.

- Request 발생 조건과 실제 전송 payload
- Opcode/Command 및 Request/Response 매칭
- 직렬화, 암호화, 압축 방식
- Response payload와 필수 필드
- Client Handler 및 응답 처리 순서
- 화면 반영과 Player State 변경 여부
- Local Server에서 재현해야 하는 최소 동작
- 성공/실패 및 재접속 등 통신 경계

## 3. 분석 범위 구분

| 영역 | 분석 수준 | 이유 |
|---|---|---|
| 로그인/인증/세션 | 상세 | 서버 연결의 시작점 |
| KCP/DH64/암복호화 | 상세 | 게임 서버 통신 재현에 필수 |
| Request/Response | 상세 | 로컬 서버의 핵심 계약 |
| Bootstrap 데이터 | 상세 | 메인 화면 진입에 필요 |
| Player State 변경 | 필요한 범위 상세 | 서버 상태 및 저장 재현 |
| 아이템/캐릭터 코드 의미 | 참고 수준 | payload 해석을 돕는 사전 |
| Word 문자열 namespace | 추가 확장 조사 불필요 | 네트워크 계약에 필요하지 않음 |
| 전체 Record 관계 | 기본 범위 제외 | 로컬 서버 통신 재현과 직접 관계 없음 |
| 게임 내부 계산/보상/확률 로직 | 기본 범위 제외 | 서버 권한 동작으로 확인된 부분만 최소 구현 |
| UI 내부 컬렉션/표시 로직 | 기본 범위 제외 | 클라이언트가 처리하면 재사용 |

## 4. 아이템 코드 분석의 위치

최근 룬 ID와 Word 문자열 확인은 아이템 코드를 사람이 읽을 수 있도록 해석한 작업이다.

예를 들어:

- `52000008` → 룬-탐욕Lv1
- `52000100` → 룬-아침 햇살Lv2

이런 이름 매핑은 네트워크 payload에서 숫자 ID가 무엇을 의미하는지 설명하는 데 유용하다.

그러나 `1/2/3/4` Word namespace를 모든 아이템에 대해 완성하거나 내부 Record 참조 관계를 전부 복원하는 것은 현재 목표가 아니다. 확인된 코드 의미는 간단한 참고 사전으로 남기고, 추가 분석은 실제 Request/Response 필드 해석에 필요할 때만 한다.

## 5. 게임 로직 구현 원칙

- Client가 이미 계산하거나 처리하는 기능은 가능한 한 원본 Client 동작을 재사용한다.
- 서버가 응답으로 제공해야 하는 데이터는 관찰된 Response 계약에 맞춰 반환한다.
- 서버 권한 Player State 변경이 필요한 경우에만 해당 변경의 최소 규칙을 구현한다.
- 내부 로직이 불명확하다는 이유만으로 전체 게임 로직을 추적하지 않는다.
- 테스트에서 특정 필드나 동작이 누락되어 클라이언트가 진행하지 못하는 경우에만 해당 부분을 추가 조사한다.

## 6. 우선순위

1. HTTP 로그인 및 인증 완료
2. KCP 세션 수립과 암복호화/압축/직렬화
3. 메인 화면 Bootstrap Request/Response
4. 초기 Player State 전달 및 클라이언트 처리 확인
5. 주요 메뉴별 Opcode와 Request/Response 계약
6. 서버 권한 상태 변경과 SQLite persistence
7. 실제 클라이언트-로컬 서버 통합 검증

기능을 확장할 때도 게임 내부의 전체 동작을 먼저 설명하려 하지 않고, 클라이언트가 보내는 요청과 기대하는 응답을 기준으로 진행한다.

## 7. 조사 종료 기준

해당 기능에 대해 다음이 확인되면 우선 정적/동적 내부 분석을 종료한다.

- 어떤 시점에 어떤 Request가 전송되는지
- Request의 Opcode와 필수 payload
- 어떤 Response가 돌아오는지
- Client가 요구하는 필드와 처리 순서
- 화면 또는 Player State에 미치는 필수 효과
- Local Server에서 재현할 최소 계약

이후에는 서버 구현과 실제 클라이언트 검증으로 이동한다. 구현/검증에서 막히는 구체적인 원인이 확인되면 그 부분만 추가 조사한다.

## 8. 기존 분석에 대한 적용

- 기존 KCP/DH64 분석은 통신 구현에 직접 필요하므로 유지한다.
- Bootstrap OpInfo와 초기 데이터 추적은 메인 화면 진입에 필요하므로 유지한다.
- 창고/룬 분석에서 확인한 아이템 이름은 코드 사전 수준으로만 활용한다.
- 룬 Word namespace의 보편 규칙을 더 확장해서 증명하는 작업은 중단한다.
- BoxStatus, 보상, 가챠 등은 내부 로직 전체를 복원하지 않고, 관련 Request/Response와 서버 상태 변경이 필요한 경계만 확인한다.

## 9. 결론

앞으로의 핵심 산출물은 게임 내부 구조 설명서가 아니라 **Opcode별 Request/Response 명세, 세션/전송 프로토콜 명세, Player State 변경 계약, Local Server 구현 및 검증 기록**이다.

아이템 코드 설명은 네트워크 데이터를 이해하기 위한 보조 정보로 활용한다. 로컬 서버 구축과 무관한 세부 데이터 구조 분석은 더 진행하지 않는다.
