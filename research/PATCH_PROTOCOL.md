# Patch Protocol

패치는 조사 결과가 충분히 쌓인 뒤에만 수행한다.

## PATCH 문서 필수 내용
- 문제 증상
- 원인 함수/주소
- 원본 제어 흐름
- 원하는 오프라인 제어 흐름
- 정확한 변경 지점
- opcode/byte 또는 수정 방법
- 왜 이 지점이 안전한지
- 예상되는 다음 상태
- 실패 시 원복 방법
- 빌드/서명 방법
- 자동 smoke test
- 사용자에게 요청할 실제 테스트

## 원칙
- 가능한 한 작은 변경부터 한다.
- 한 번에 여러 독립 게이트를 바꾸지 않는다.
- 패치 하나당 관찰 가능한 효과를 하나로 만든다.
- 원본 바이너리는 Git에 저장하지 않는다.
- Codex는 패치 후 결과와 생성 APK의 로컬 경로/해시를 보고한다.
